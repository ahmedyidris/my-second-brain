### 3. [data-gap/contradiction] Voice-engine wake-word choice contradicts Jarvis X's own sovereignty principle — RESEARCHED, FIXED
**Location:** `wiki/jarvis-x-voice-engine.md` ("Offline core" table, "Wake word" row).
**Detail:** The page listed "Porcupine / openWakeWord" as interchangeable options for hands-free wake-word detection. Fresh research (Picovoice's own docs + GitHub repo, corroborated by openWakeWord's own GitHub repo) found they are not equivalent: **Porcupine requires a Picovoice AccessKey and periodic online activation**; **openWakeWord needs no account or key at all**. [[jarvis-x]] states as a sovereignty principle "Zero-subscription — must boot and function with zero cloud keys," and this same voice-engine page frames its offline core as "always works." Porcupine's key requirement is in tension with both claims.
**Fix applied:** Added an explicit "Wake word: Porcupine vs openWakeWord" subsection to `wiki/jarvis-x-voice-engine.md` laying out the contradiction plainly and recommending openWakeWord as the default for a strict zero-cloud-key build — flagged as a recommendation, not a silent resolution, since the actual engine choice is a human call per this vault's guardrails.
**Sources:** `github.com/Picovoice/porcupine`, `picovoice.ai/docs/faq/porcupine/`, `github.com/dscripka/openWakeWord` (all accessed 2026-08-16).
